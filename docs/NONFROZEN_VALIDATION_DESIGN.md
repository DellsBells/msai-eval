# Non-frozen validation task — design (the keystone gating item)

*Draft for sign-off by both tracks before build. Goal: exercise the ONE tier Phase 4 couldn't —
the resolution / GUM `U`-band (compare's whole reason to exist) — on real, non-frozen data.*

## Why Phase 4 (brand-ID) couldn't do it

Brand-ID is **frozen** (a model reads the same brand run-to-run) and **near-binary** (right/wrong on
a [0,1] overlap). So there was no genuine run-to-run repeatability and no graded quality to resolve —
`compare()` correctly refused, and `gauge_judgement` read NOT ACCEPTABLE. We never tested whether the
`U`-band can *resolve a real sub-point difference*, which is the point of the adopt-U work.

The fix is a task that is **graded** (a real 1–5 quality scale, not binary) and **genuinely variable
run-to-run** (subjective scoring at temperature > 0), with treatments that differ by a **sub-point
delta** so the `U`-band's resolving power is actually on trial.

## The task: graded listing-quality scoring

A judge LLM scores the **quality of a generated resale listing** (title + description + attributes)
against a fixed rubric, 1–5, at temp > 0. This is subjective → real repeatability; graded → real
resolution; and listing quality genuinely varies by generator config → a sub-point delta to resolve.

**Rubric (1–5, anchored so judges share a scale):** 5 = accurate, complete, well-written, sells the
item; 4 = good, minor gaps; 3 = usable, notable omissions/errors; 2 = poor, missing or wrong key
attributes; 1 = unusable/misleading. (Anchors written out so judge disagreement is signal, not rubric noise.)

## Measurement model (maps cleanly onto MSAI)

| MSAI role | This task |
|---|---|
| **items** (parts) | N listings spanning a real quality range (some great, some poor) |
| **judges** (appraisers) | a FIXED panel of 4–5 LLM scorers, each rating quality 1–5, **≥3 trials at temp 0.7** |
| **treatments** (for compare) | the listing **GENERATOR** configs being A/B'd (e.g. resale-vlm vs qwen vs Haiku; or q4 vs q8; or ±preprocessing) — the judge panel is held fixed |
| **reference** | **human gold quality** — 2–3 people grade a sample on the same rubric → value + `u_ref` from inter-grader spread (`reference_from_labels`) |

Note the two distinct panels: the **judge panel** (scores quality — drives reliability / proficiency /
uncertainty) and the **generator configs** (the treatments — drive compare). Don't conflate them.

## What each tier finally gets exercised

- **reliability** — judges scoring 1–5 at temp 0.7 have real within-cell variance → `gauge_judgement`
  produces a genuine ACCEPTABLE / CONDITIONAL / NOT-ACCEPTABLE verdict (not frozen-refused).
- **uncertainty_budget** — a real repeatability term (not 6%), so the `U`-band reflects all three of
  repeatability / reproducibility / resolution; the dominant-lever call is finally meaningful.
- **compare (THE point)** — config A vs config B listings, scored by the fixed panel. A sub-point
  quality delta either clears the `U`-band (REAL) or sits inside it (within noise). **This is the first
  real test of whether the GUM `U`-band resolves a true small difference** — the gating validation.
- **proficiency / accuracy** — each judge vs the human-gold reference (`En` carrying the gold's `u_ref`);
  the fitness gate decides whether the human gold is tight enough to arbitrate.

## Staging (so the U-band gets tested NOW, not after a human-grading pipeline)

- **Stage A — buildable immediately (no humans):** judge panel scores quality 1–5 @ temp 0.7, ≥3
  trials, over listings generated by ≥2 configs. Run reliability + uncertainty + **compare** on the
  config deltas. This exercises the resolution/`U`-band tier — the gating item — with zero human
  dependency. Accuracy/proficiency-vs-truth are deferred (no external reference yet).
- **Stage B — adds the reference:** 2–3 people grade a ~20-listing sample on the rubric →
  `reference_from_labels` → the gold + `u_ref`. Now accuracy + proficiency-vs-truth + the fitness gate
  run, and the U-band can be checked against a traceable reference, not just config-vs-config.

## Success criteria (what "validated" means here)

1. The judge panel is **not frozen** (within-cell SD comfortably above the relative deterministic gate)
   — confirming a graded subjective task actually exercises repeatability.
2. `compare()` **qualifies the gauge** (not provisional) and returns a real REAL/within-noise verdict on
   at least one config pair — the U-band resolving (or correctly refusing to resolve) a sub-point delta.
3. The honesty firewalls still hold (no overclaim): the budget names the right lever; a within-noise
   verdict is never read as "equivalent".
4. (Stage B) the human gold's fitness vs the judge gauge is reported; accuracy is labeled by it.

## Honest caveats (write these into the eventual VALIDATION §5)

- Human grading is small-n and itself noisy — `u_ref` from 2–3 graders is coarse; that's carried, not hidden.
- The rubric is the experiment's load-bearing part; ambiguous anchors turn into judge disagreement that
  looks like gauge noise. Pilot the rubric on a few listings first.
- A clear sub-point delta isn't guaranteed to exist between configs — if all configs produce similar
  quality, "within noise" is the honest (and still informative) result.
